1. Why this matters for Qualcomm work

In Task 04 you built a small version of the deployment trick yourself. Your Part 6 wrapper froze one decode graph with a padded cache, an additive mask, and position inputs. You wrote the new K/V slice into the cache on the host — the Python side that drives the graph.

Qualcomm ships the real version of that wrapper. It is called an adapter: code that wraps the original Hugging Face model so it exports to a static graph the NPU can compile. Qualcomm does not retrain Qwen. It patches and repackages it.

Every later task stands on this code. Task 06 explains its quantization recipe. Task 07 runs its export script. If you can read this adapter, the rest of the stack stops being a black box.

4. A simple mental model

Think of the adapter as three floors of one building.

FloorWhereWhat lives there
Top: this model only src/qai_hub_models/models/qwen3_0_6b/model.py Constants (NUM_LAYERS = 28, HEAD_DIM = 128…) and thin subclasses that just fill those constants in.
Middle: the Qwen3 family src/qai_hub_models/models/_shared/qwen3/model.py Qwen3-specific patches: split-head attention, the RoPE bypass, the chat template, the mask multiply.
Ground: any LLM src/qai_hub_models/models/_shared/llm/model.py Family-agnostic machinery: the graph input spec, the split/Part system, export and quantization plumbing.

Read from the top down. The 0.6B file is short because everything reusable was pushed downstairs.

Key idea. The adapter changes the model's form, never its meaning. Same weights, same math. Different module types, different tensor layouts, different interface — so the graph compiles well on the NPU.

The names are long but regular. PreSplit means the whole model before it is cut into parts. Part means one deployed piece. Collection groups the parts.

5.3 What monkey_patch replaces

A monkey patch is a runtime swap: assign a new class or function over an existing name in another module. No fork of Hugging Face needed. Qwen3Base.monkey_patch (in _shared/qwen3/model.py) does four swaps inside transformers.models.qwen3.modeling_qwen3:

OriginalReplacementWhy
Qwen3AttentionSHAQwen3Attention Split-head attention. Heads compute separately, and each of q_proj, k_proj, v_proj, o_proj becomes a 1×1 nn.Conv2d with the same weights. Section 5.3.1 gives Qualcomm's stated reasons.
Qwen3RotaryEmbedding.forwarda bypass that returns position_ids unchanged RoPE cos/sin tables are computed on the host and fed in as graph inputs. The graph only applies them.
apply_rotary_pos_embQcQwen3_apply_rotary_pos_emb Applies the precomputed cos/sin in the split-head layout.
Qwen3MLP, Qwen3ForCausalLM QCQwen3MLP, QCQwen3ForCausalLM Export-friendly variants of the MLP and the top-level model.
Watch for. Your Task 04 export needed no patches because you traced the stock model. Qualcomm patches first, then exports — so the traced graph already has the NPU-friendly form.

5.3.1 Why these swaps — Qualcomm's own reasons

The reasons below come from Qualcomm's LLM onboarding guide, which ships inside your pinned clone: tutorials/llm/onboarding.md. It is written for Llama but names the same adaptations this Qwen3 adapter applies. Statements from that guide are marked as facts. The rest is labeled inference.

First, the core idea. The compiler does not see "attention". It sees the traced list of ops. It matches runs of ops against its kernel library and fuses them into single kernel calls. The same math, arranged differently, matches different kernels — or none. That is why arrangement matters at all.

Why the stock model is a bad fit, point by point:

  • Head-as-axis attention. Fact from the guide: Hugging Face implements multi-head attention "by representing each head as an axis in our tensors. This is highly disadvantageous for NPUs. Much better performance can be achieved if each head is a separate sub-graph" — which is what SHA builds, as Python lists with one head per element. The guide states no mechanism. Inference: the head axis forces view, transpose, and reshape ops between every step. Those compute nothing. They move bytes and break kernel fusion. One small sub-graph per head removes them from the trace.
  • RoPE computed inside the graph. Fact: the Genie runtime requires position_ids_cos and position_ids_sin as separate inputs, with the duplicated half removed "to reduce I/O overhead" — that is why their last dimension is head_dim / 2 = 64. Hugging Face cannot pass separate cos/sin tensors. So the adapter patches Qwen3RotaryEmbedding.forward into a pass-through and patches apply_rotary_pos_emb to read the compact format. The host computes the tables once. The graph only multiplies and adds.
  • Cache layout and cache outputs. Fact: both are Genie I/O requirements — "Keys are transposed" on input, and outputs are "transposed and only new tokens are output". Hugging Face would output the whole context-length cache every step. The deployed graph outputs only the seq_len new positions, and the host writes them into the buffer — your Part 6 loop.
  • The mask value. Fact: "Mapping the real range (-∞, 0] to a quantized range is impractical." So −∞ becomes a finite stand-in. −50 typically works for Llama-family models. Qwen 2.5's activations ran naturally larger, so its mask had to be scaled inside the network — that is the job of the attention_mask_multiplier multiply you can read in Qwen3Base.forward.
  • 1×1 convolutions and rank-4 RMSNorm. Fact, and a correction to a common guess: the guide lists both as adaptations "done for historical reasons" that "may no longer be needed". The conv swap is "still relevant for v68" — an older Hexagon generation. So do not credit the conv rewrite for today's speed. The load-bearing changes are the ones above.
  • Model size. Fact: the NPU is a 32-bit co-processor, so one compiled binary is limited to about 1–2 GB. That is why parts exist, and "the first split always contains a single Gather operation" — the embedding. That is your Part 1.

The specific way, in one list. "NPU friendly" means five habits, all visible in this adapter:

  1. Fixed shapes everywhere (Task 04's lesson).
  2. One head per sub-graph — no giant head-axis tensor shuffled by reshapes.
  3. Only values quantization can represent — a finite mask, no ±∞.
  4. Constant tables and bookkeeping on the host — RoPE cos/sin, mask building, cache writes.
  5. Pieces small enough for a 32-bit co-processor.

One more name to keep: the guide calls the decode graph AR-1 and the prefill graph AR-128 (autoregressive, sequence length 1 or 128). You will meet those names again in the compiled bundle in Tasks 07 and 08.

5.4 The real graph contract

The contract is built by LLMBase._get_input_spec in _shared/llm/model.py. Two graphs are exported, set by DEFAULT_EXPORT_SEQUENCE_LENGTHS = [128, 1] with DEFAULT_CONTEXT_LENGTH = 4096:

  • Prefill graph: sequence_length = 128. A long prompt runs through it in 128-token chunks.
  • Decode graph: sequence_length = 1. One token per step, like yours.

Decode-graph inputs (with L = 1, context 4096, embed_dim = HEAD_DIM // 2 = 64):

InputShapedtype
input_ids(1, 1)int32
attention_mask(1, 1, 1, 4096)float32
position_ids_cos(1, 1, 1, 64)float32
position_ids_sin(1, 1, 1, 64)float32
past_key_{i}_in × 28(8, 1, 128, 4095)float32
past_value_{i}_in × 28(8, 1, 4095, 128)float32

That is 4 + 56 = 60 inputs. Outputs are logits plus past_key_{i}_out and past_value_{i}_out per layer = 57 outputs. The outputs carry only the new slice: the shared forward returns keys[:, :, -seq_len:, :], permuted. The host writes it into the big cache buffer — exactly your Part 6 loop.

Note the cache length: context_length - sequence_length = 4095 for decode, 3968 for prefill. The current chunk's K/V comes out as fresh output, so the input buffer never needs those slots.

5.5 Yours vs Qualcomm's — the same design, four twists

IdeaYour Part 6 wrapperQualcomm's adapter
Positionsposition_ids integer; RoPE runs inside the graphposition_ids_cos / position_ids_sin computed on the host by RopeEmbedding; the table lookup leaves the graph
Maskadditive; hidden = torch.finfo(torch.float32).min additive; Qwen3PositionProcessor clips it with attention_mask.clip(-50, 0). −3.4e38 cannot survive 16-bit activation quantization. −50 is "minus infinity enough" after softmax.
Cache layout[1, H_kv, MAX_LEN, D], batch first heads first; the key is stored transposed: (8, 1, 128, 4095) puts head_dim before the cache slots. Inference: attention needs K transposed for Q·KT, so storing it transposed removes a permute per step.
New K/Vnew_key_i [1, H_kv, 1, D], host writes the slotpast_key_{i}_out = last seq_len slice, host writes the slots. Same job.

5.6 Two parts, one model

NUM_SPLITS = 2. Part 1 is the token embedding alone. Part 2 is all 28 transformer layers plus the LM head. Split ONNX file basenames use SPLIT_MODEL_NAME = "Qwen3_0_6B", giving names like Qwen3_0_6B_1_of_2.onnx.

Why split there? The embedding is one huge lookup table (151,936 × 1,024) with integer input — a different workload from the float layer stack. A comment in model.py adds a practical reason: "2 splits fit the HTP at this size; bump NUM_SPLITS if on-device load hits err 1002". Bigger family members need more splits purely for memory.

5.7 Where quantization hooks in (preview of Task 06)

  • SPINQUANT_CONFIG = {"enable_r1": False, "enable_r2": True, "enable_r3": True} — set on the quantizable class, applied inside quantize().
  • get_weight_optimization_data → plain Wikitext. Feeds AdaScale.
  • get_calibration_data → InterleavedGeneratedWikitext. Feeds final calibration.
  • ada_scale_num_rmsnorm_per_blk = NUM_ATTN_HEADS + NUM_KEY_VALUE_HEADS + 1 = 25 — a split-head consequence: each head now has its own norm to scale.

6. One worked example: a token's journey on device

  1. Host: tokenizer turns text into ids. Host computes the RoPE cos/sin rows for the current positions and builds the clipped additive mask.
  2. Part 1 graph: input_ids → embedding lookup → hidden vectors.
  3. Part 2 graph: hidden vectors + mask + cos/sin + 56 cache tensors → 28 layers → LM head → logits + 56 new K/V slices.
  4. Host: picks the next token from logits, writes the 56 slices into the cache buffers, advances the position. Repeat from step 1's cos/sin.

Compare with your Part 6 notebook cell. Steps 1 and 4 are your loop. Steps 2 and 3 are your one graph, split in two.

12. Knowledge check

  1. Why does the graph take position_ids_cos and position_ids_sin instead of integer positions?
    AnswerThe RoPE table lookup was moved to the host. monkey_patch bypasses Qwen3RotaryEmbedding.forward, and Qwen3PositionProcessor computes cos/sin outside the graph. The graph only applies them. Less work and fewer op types inside the compiled graph.
  2. The decode graph's cache inputs hold 4095 slots, not 4096. Why?
    Answercontext_length - sequence_length. The current token's K/V leaves the graph as fresh output (past_key_{i}_out), so its slot never needs to be an input. Your Part 6 wrapper did the same with new_key_i.
  3. Why does the mask use clip(-50, 0) instead of the float32 minimum you used?
    AnswerThe deployed model quantizes activations to 16 bits. A range that must cover −3.4e38 wastes all its precision. After softmax, −50 already zeroes a position, so it is a safe stand-in for minus infinity.
  4. What is Part 1 of the deployed model, and why is it separate?
    AnswerThe token embedding alone (Qwen3_0_6B_Part1_Of_2, part_id = 1). It is a huge integer-indexed lookup table, a different workload from the float layer stack, and the split keeps each piece inside HTP memory limits (the code notes err 1002 when a piece is too big).
  5. Which class would you edit to change the calibration text, and which method?
    AnswerQwen3_0_6B_QuantizablePreSplit.get_calibration_data in qwen3_0_6b/model.py. It currently returns data built from InterleavedGeneratedWikitext.

14. Page glossary and sources

Adapter
Code that wraps an existing model to change its form — module types, layouts, interface — without changing its weights or meaning, so it can deploy on a target runtime.
Monkey patch
Replacing a class or function in another module at runtime by assigning over its name. Used here to swap Hugging Face internals for NPU-friendly versions without forking.
Split-head attention (SHA)
An attention rewrite where each head computes separately and the q/k/v/o projections become 1×1 convolutions with the original weights.
Input spec
Qualcomm's name for the graph contract: an ordered mapping from input name to shape and dtype, produced by get_input_spec.
Part (model split)
One deployed piece of a model that was cut for memory or workload reasons. Parts run in sequence on the device; here Part 1 is the embedding, Part 2 is everything else.
Host
The CPU-side program that drives the compiled graphs: tokenization, RoPE tables, mask building, cache writes, token selection.
