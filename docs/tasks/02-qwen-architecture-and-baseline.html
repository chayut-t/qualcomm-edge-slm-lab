Task 02 — Qwen architecture and Hugging Face baseline

Lab: notebooks/02_qwen_architecture_baseline.ipynb · Estimated time: 2.5–3 hours (includes a ~1.4 GB model download)

1. Why this matters for Qualcomm work

In Task 07 you will fetch a compiled W4A16 bundle. That bundle freezes the exact tensor shapes you study today: 16 query heads, 8 key/value heads, head dimension 128. If a shape in an export error looks like [1, 8, 128, 128], today's task is what lets you read it.

Grouped-query attention is not a detail. It halves the KV cache, and KV-cache size is a main memory cost on an NPU. Qualcomm splits the model into two deployed parts at the embedding boundary — a boundary you will see in this task as real modules.

You also record a deterministic float generation today. It becomes the accuracy baseline that later quantized outputs are compared against (PROJECT_INIT.md Section 8.4).

4. A simple mental model

Think of the model as a factory line for one job: given the tokens so far, score every possible next token.

  • Embedding — a lookup table with 151,936 rows (one per token in the vocabulary) and 1,024 columns. A token id picks a row. Text becomes numbers here.
  • 28 decoder blocks — identical stations. Each one has two tools: attention (look at earlier tokens and mix in what is relevant) and an MLP (transform the mixed result). Small normalization layers keep the numbers stable between tools.
  • LM head — the same 151,936 × 1,024 table used in reverse. It turns the final 1,024-number state back into 151,936 scores, one per vocabulary token. These scores are the logits.
  • Greedy decoding — take the highest score. Same input, same output, every time. That determinism is what makes it a baseline.
Key idea Grouped-query attention (GQA): the model has 16 query heads but only 8 key/value heads. Each K/V pair serves 2 query heads. Quality stays close to full attention, but the KV cache — the memory that grows with every generated token — is cut in half. That trade is exactly why GQA models fit on phones.

5. Exact technical details

All values below come from the model's config.json. The notebook asserts every one of them.

Config fieldValueMeaning
num_hidden_layers28decoder blocks
hidden_size1,024width of the state between blocks
num_attention_heads16query heads
num_key_value_heads8K/V heads (GQA)
head_dim128explicit width of one head
intermediate_size3,072MLP inner width
vocab_size151,936tokens the model knows
rope_theta1,000,000RoPE base frequency
max_position_embeddings40,960longest trained position
tie_word_embeddingstrueembedding and LM head share one weight

Watch the head math. In many models head_dim = hidden_size / num_attention_heads. Here that would give 1024 / 16 = 64. But Qwen3 sets head_dim = 128 explicitly. So attention works in a wider space than the hidden state:

q_proj: 1024 -> 16 * 128 = 2048
k_proj: 1024 ->  8 * 128 = 1024
v_proj: 1024 ->  8 * 128 = 1024
o_proj: 2048 -> 1024

Shape formulas, for a batch of 1 and sequence length S (the number of input tokens):

TensorFormulaWith S = 8
input ids[1, S][1, 8]
hidden state[1, S, hidden_size][1, 8, 1024]
Q after reshape[1, 16, S, 128][1, 16, 8, 128]
K, V after reshape[1, 8, S, 128][1, 8, 8, 128]
attention weights[1, 16, S, S][1, 16, 8, 8]
logits[1, S, vocab_size][1, 8, 151936]

Every symbol: 1 is the batch size. S is the sequence length. 16 and 8 are query and K/V head counts. 128 is head_dim. 151936 is the vocabulary size.

RoPE (rotary position embedding), concept level: the model must know token order, because attention alone treats input as a set. RoPE rotates each Q and K vector by an angle that depends on its position. Nearby tokens get similar rotations, so their dot products stay high. rope_theta = 1,000,000 sets how slowly those angles change across positions — a large base supports long contexts. RoPE touches only Q and K. V is never rotated.

Qwen3 detail: each block applies a small RMSNorm (a normalization that rescales a vector by its root-mean-square) to every Q head and K head before RoPE. You will see q_norm and k_norm with weight shape [128] in the module tree.

6. One worked example

Count the attention parameters of one block by hand, then let the notebook check you:

q_proj: 1024 * 2048 = 2,097,152
k_proj: 1024 * 1024 = 1,048,576
v_proj: 1024 * 1024 = 1,048,576
o_proj: 2048 * 1024 = 2,097,152
q_norm + k_norm:  128 + 128 = 256
attention total per block  = 6,291,712

28 blocks of attention ≈ 176 M parameters. The embedding table alone is 151,936 × 1,024 ≈ 156 M — about a quarter of the whole model. Because the LM head is tied, that table is stored once, not twice.

9. How to read the notebook

Six parts, in order:

  1. Setup — checks /Volumes/T9, sets the cache location, creates results/ paths.
  2. Load — tokenizer and model, float32 on CPU, with attn_implementation="eager" so attention weights are visible.
  3. Config and parameters — asserts the table from Section 5, counts parameters per component, proves the embedding and LM head share one tensor with is.
  4. Shape probe — run_shape_probe(seq_len) runs a real forward pass and reads Q/K/V, attention, and logits shapes from live tensors. Results append to results/02_shape_comparison.json.
  5. PARAMETER cell — rerun the probe with your own SEQ_LEN.
  6. Baseline generation — greedy decoding, thinking mode off, run twice, asserted identical, saved to results/02_generation_baseline.json.

12. Knowledge check

Optional. Answers are hidden until you click.

1. K and V have shape [1, 8, S, 128] but Q has [1, 16, S, 128]. How does attention combine them?

Each K/V head serves a group of 16 / 8 = 2 query heads. The K/V tensors are repeated (or indexed) per group, so every query head still gets keys and values. That sharing is grouped-query attention.

2. Why does q_proj output 2048 numbers when the hidden state is only 1024 wide?

Because head_dim is explicitly 128, and 16 heads × 128 = 2048. Qwen3 gives attention a wider space than the hidden state and maps back with o_proj (2048 → 1024).

3. What does tying the embedding and LM head save, and what stays the same?

It saves storing one 151,936 × 1,024 matrix (~156 M parameters). The compute stays the same — the LM head still multiplies by the full table.

4. RoPE rotates which tensors, and why not V?

Only Q and K. Position must influence the attention scores (Q·K dot products). V carries content that gets mixed after scoring, so rotating it would distort content without adding position information.

5. Why does this task's greedy generation matter for Task 09's benchmark on the NPU?

It is the float accuracy baseline. The W4A16 model's output quality is judged against this local Hugging Face float output, because no float device asset exists for this model (Task 01 finding).
