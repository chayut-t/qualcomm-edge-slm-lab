Task 08 — QAIRT and GenieX on QDC

Lab: interactive device session — you drive a real Snapdragon phone over adb, command by command · Estimated time: 2–3 hours; the session itself about 30–45 minutes

1. Why this matters for Qualcomm work

Task 07 measured single graph passes on a hosted device. That is a test bench: one graph, fake inputs, no tokenizer, no sampling. This task drives the whole car — and you hold the wheel. GenieX runs the full generative loop — tokenize, prefill, decode token by token, sample — on a phone in QDC (Qualcomm Device Cloud) that you control live through an SSH tunnel and adb. Every push, every environment variable, every benchmark run is a command you type.

The core question: what is compiled into the bundle, and what does GenieX control at runtime? You will answer it twice. Once on paper, in a generated execution manifest. Once in numbers, by running the same bundle at two context lengths and watching the speed change.

2. What you will understand after this task

  • How the three runtime layers stack: QNN context binary → QAIRT → GenieX.
  • Which choices were frozen at compile time and which are still open at run time.
  • How a QDC interactive session works: reservation, SSH tunnel, remote adb, minutes.
  • What TTFT, prefill tokens/s, and decode tokens/s each measure, and why they differ.
  • How the full-loop numbers relate to the raw graph timings from Task 07.

3. Prerequisites

  • Task 07: the W4A16 bundle is on T9 at artifacts/task07/qwen3_0_6b-geniex_qairt-w4a16-qualcomm_snapdragon_8_elite.
  • Task 07: you know each context binary holds ten graphs (prompt_ar128 and token_ar1 at context lengths 512/1024/2048/3072/4096).
  • Task 07 numbers to compare against: one token_ar1_cl4096 pass through part2 took 24,809 µs. One prompt_ar128_cl4096 pass took 47,254 µs for 128 tokens.
  • QDC account setup, already done: free minutes unlocked for Snapdragon 8 Elite (1000 min), and an SSH key generated in User Settings (the qdc_id_*.pem file you downloaded).
  • adb on your Mac (you have it at /opt/homebrew/bin/adb).

4. A simple mental model

Think of a music box. The QNN context binary is the metal cylinder: the pins are fixed. The chipset is the box the cylinder was machined for; it fits no other box. QAIRT is the mechanism that turns the cylinder. GenieX is the hand that winds it, picks which of the five compiled songs to play (the context length), and decides when to stop (how many tokens). In this task the hand is yours, literally: you type the winding commands into the phone yourself. You can wind faster or slower. You cannot add a note. Adding a note means machining a new cylinder — recompiling.

5. Exact technical details

5.1 The three runtime layers

LayerWhat it is hereDecided when
QNN context binary part1_of_2.bin + part2_of_2.bin: compiled graphs, W4A16 weights, quantization encodings Compile time
QAIRT Runtime version 2.45.0.260326154327, backend QnnHtp, extensions in htp_backend_ext_config.json SDK version fixed when the bundle was built
GenieX The generative interface. Plugin qairt loads the bundle. The benchmark tool is geniex-bench. Run time

Fact: all three names above come from the bundle's own metadata.json and genie_config.json. Your manifest tool copies them from there.

5.2 Compiled in vs chosen at run time

Compiled into the binaries (cannot change) Runtime configuration (can change)
Context lengths: 512, 1024, 2048, 3072, 4096 only Which one to use: -c 512 or -c 4096
Graph shapes: prefill 128 tokens, decode 1 token How many tokens to generate: -n 128
W4A16 weights and their encodings The prompt text (--prompt-file)
Chipset: sm8750, HTP version 79 Sampler: temp 0.8, top-k 40, top-p 0.95, seed 42 (in genie_config.json)
KV layout: kv-dim 128, uint8 cache CPU threads for the non-NPU parts: n-threads 3
Key idea

The right column is exactly what genie_config.json and the geniex-bench flags hold. Editing them needs no recompile. Everything in the left column would need a new AI Hub compile job for a new binary. This split is the answer to the task's core question.

5.3 Anatomy of a QDC interactive session

  1. Reserve. In the QDC web UI you start a New Interactive Session on the Snapdragon 8 Elite (QRD8750). QDC flashes a phone and attaches it to a host in their lab. Your minute budget ticks from start to the moment you press Complete Session.
  2. Tunnel. The session's Connect dialog shows an SSH command. It forwards one local port to the remote adb server that is wired to your phone: 
    ssh -i <PEM> -L <PORT>:sa<SESSION_ID>.sa.svc.cluster.local:5037 -N sshtunnel@ssh.qdc.qualcomm.com
    <PEM> is your QDC SSH private key. The tunnel window must stay open the whole session; closing it cuts adb off.
  3. Drive. In a second terminal your local adb talks through that port. Every adb shell command runs on the real phone.
  4. Collect and release. adb pull the results, clean the phone, press Complete Session. Minutes stop.

5.4 What one benchmark run does on the phone

  1. GenieX tokenizes sample_prompt.txt (about 38 tokens).
  2. Prefill: the prompt_ar128_cl<ctx> graphs run once through part1 then part2. The time until the first generated token is TTFT (time to first token).
  3. Decode: the token_ar1_cl<ctx> graphs run once per token, 128 times. Tokens divided by this time is decode tokens/s.
  4. geniex-bench repeats the run 3 times (-r 3) and writes one JSON cell per (model, context length) with the medians.

Inference from Task 07 numbers: one decode pass through part2 alone took 24.8 ms, so decode can never beat about 40 tokens/s at cl4096. The measured number will be lower — GenieX adds part1, KV-cache writes, sampling, and tokenizer work every step. Confirm this against your own measurement.

5.5 The result cells

Each cell is a JSON file with "schema_version": "3" in /data/local/tmp/QDC_logs/results on the phone. The fields you keep:

  • ttft_ms — median milliseconds to the first token.
  • prefill_tps — median prompt tokens per second during prefill.
  • decode_tps — median generated tokens per second.
  • prompt_tokens, gen_tokens — how many of each actually ran.

6. One worked example (illustrative numbers)

The values below are invented to show the shape. Yours will differ. A cell file like:

{
  "schema_version": "3",
  "cell_id": "qwen3_0_6b-qairt-npu-c512",
  "plugin": "qairt",
  "device": "npu",
  "agg": {
    "ttft_ms":     {"median": 205.0},
    "prefill_tps": {"median": 190.0},
    "decode_tps":  {"median": 31.0},
    "prompt_tokens": {"median": 38},
    "gen_tokens":    {"median": 128}
  }
}

parses to one row: context 512, TTFT 205 ms, decode 31 tokens/s. Reading it: 38 prompt tokens took about 0.2 s to prefill, then each new token took about 32 ms. Compare that 32 ms to the 24.8 ms raw part2 pass from Task 07 — the difference is everything GenieX does around the graph.

7. Think before running (optional)

The cl512 decode graph attends over at most 511 cached positions. The cl4096 graph always attends over 4095, even for a 38-token prompt. Which context length should decode faster? By roughly how much, if attention cost dominated? Keep your guess in your head and check it against the two cells.

8. Hands-on instructions

Run everything from the repo root. Steps 1–2 cost no QDC minutes. Do them first and completely — session time should be spent running, not preparing.

Step 1 — Offline checks

df -h /Volumes/T9
uv run pytest tests/test_task08_tools.py -q

9 tests, no network. They prove the package builder and the parser work before you reserve anything.

Step 2 — Build the device package and the manifest

uv run python -m edge_slm_lab.qdc_artifact \
  --out-dir /Volumes/T9/qualcomm-edge-slm-lab/artifacts/task08

This downloads geniex-bench (86 MiB, one time), unpacks it into device_pkg/, writes the two matrix files, and prints the full session command list (also saved to commands.txt). Then open results/08_execution_manifest.json and find the five sections: qnn_context_binary, qairt, geniex, chipset, runtime_configuration. Each has a fixed_at or chosen_at line. That file is the paper answer to the core question.

Step 3 — Reserve the session (web UI)

  1. QDC → Interactive Sessions → new session → platform Mobile → device Snapdragon 8 Elite (QRD8750).
  2. Device Configuration: turn Wifi Enabled on is not needed — the phone needs no internet; everything arrives over adb.
  3. Start the session. When it shows Running, open the Connect dialog. It shows your exact tunnel command with the session ID and port filled in.
Warning

Minutes tick from now until you press Complete Session. Everything you need to type is already in commands.txt. If something fails twice, do not debug on the clock: pull what you have, complete the session, and ask Claude.

Step 4 — Tunnel and connect (2 terminals)

Terminal 1 — the tunnel (from the Connect dialog; template):

ssh -i <PEM> -L <PORT>:sa<SESSION_ID>.sa.svc.cluster.local:5037 -N sshtunnel@ssh.qdc.qualcomm.com

It prints nothing when it works. Leave it open. Terminal 2 — point adb at the tunnel and check:

adb kill-server
export ADB_SERVER_SOCKET=tcp:127.0.0.1:<PORT>
adb devices

adb devices must list exactly one device. That is the phone in Qualcomm's lab.

Step 5 — Push, prepare, run (terminal 2)

These are the commands from commands.txt. The two pushes are the slow part (86 MiB of tools, then the 750.8 MiB bundle):

adb push /Volumes/T9/qualcomm-edge-slm-lab/artifacts/task08/device_pkg/. /data/local/tmp/pkg-geniex
adb push /Volumes/T9/qualcomm-edge-slm-lab/artifacts/task07/qwen3_0_6b-geniex_qairt-w4a16-qualcomm_snapdragon_8_elite/. /data/local/tmp/pkg-geniex/qairt_bundles/qwen3_0_6b

adb shell "find /data/local/tmp/pkg-geniex/bin -type f -exec chmod 755 {} +"
adb shell "cp /data/local/tmp/pkg-geniex/lib/qairt/htp-files/*.so /data/local/tmp/pkg-geniex/lib/"
adb shell "cp /data/local/tmp/pkg-geniex/lib/llama_cpp/*.so /data/local/tmp/pkg-geniex/lib/"
adb shell "mkdir -p /data/local/tmp/geniex-cache /data/local/tmp/QDC_logs/results"

Now the two benchmark runs. Watch the first one's output live — you will see the model load onto the NPU and the tokens stream:

adb shell "cd /data/local/tmp/pkg-geniex && LD_LIBRARY_PATH=/data/local/tmp/pkg-geniex/lib:/data/local/tmp/pkg-geniex/lib/llama_cpp:/data/local/tmp/pkg-geniex/lib/qairt ADSP_LIBRARY_PATH=/data/local/tmp/pkg-geniex/lib GENIEX_PLUGIN_PATH=/data/local/tmp/pkg-geniex/lib ./bin/geniex-bench --matrix-file /data/local/tmp/pkg-geniex/matrix-512.tsv --output-json-dir /data/local/tmp/QDC_logs/results -r 3 -c 512 -n 128 --prompt-file /data/local/tmp/pkg-geniex/qairt_bundles/qwen3_0_6b/sample_prompt.txt --mm-data-dir /data/local/tmp/geniex-cache --chipset 'qualcomm-snapdragon-8-elite'"

Then the same command with matrix-4096.tsv and -c 4096 (it is the next line in commands.txt).

Try it

That second run IS the comparison experiment: one variable (context length), two values, same phone, same prompt, same bundle. Note the difference you see in the live output before you even parse the JSONs.

Step 6 — Pull, clean, release

adb pull /data/local/tmp/QDC_logs/results /Volumes/T9/qualcomm-edge-slm-lab/artifacts/task08/pulled
adb shell "rm -rf /data/local/tmp/pkg-geniex /data/local/tmp/geniex-cache"

Then press Complete Session in the web UI. The minute counter stops only then.

Step 7 — Record the evidence

uv run python -m edge_slm_lab.qdc_results \
  /Volumes/T9/qualcomm-edge-slm-lab/artifacts/task08/pulled/results \

This parses the cells and writes results/08_qdc_geniex.json. If a run failed on the phone, record it anyway with --note describing the error — a recorded failure is valid evidence.

If the session cannot start or the tunnel never connects, stop and tell Claude exactly which step failed and with what message. That is a real external blocker. 9. How to read the generated Python files

  • src/edge_slm_lab/qdc_artifact.py — top to bottom: constants copied from the pinned repo (plugin, alias, on-device paths), build_matrix_tsv (the one line telling geniex-bench what to run), bench_command (the full on-device call with its three environment variables), session_commands (your checklist), download_bench + extract_bench (fetch and unpack the tool), and build_execution_manifest (reads only the bundle's own metadata — nothing is invented).
  • src/edge_slm_lab/qdc_results.py — parse_cell keeps only whitelisted metric fields from each schema-3 cell, exactly like Task 07's hub_job_record.py; records merge by session ID so failures and successes accumulate.
  • Reference for both: the pinned originals in src/qai_hub_models/models/_shared/llm/qdc/ — the on-device steps in device_scripts/geniex_pytest/test_geniex_bench_android.py are what Qualcomm's own automation runs; your session does the same steps by hand.

10. Outputs to inspect

  1. results/08_execution_manifest.json — the five sections, and inside qnn_context_binary the two sha256 values. They must match your Task 07 manifest (results/07_artifact_manifest.json): same bytes, new runtime.
  2. The live geniex-bench output during the run — model load, then the perf summary lines per repetition.
  3. results/08_qdc_geniex.json — two cells. Check:

  4. One raw cell JSON under artifacts/task08/pulled/results on T9 — see the full structure your parser filtered.

11. Common mistakes and debugging clues

  • adb devices shows nothing — the tunnel is not up, or adb is not pointed at it. Check terminal 1 is still running, and that ADB_SERVER_SOCKET matches the port in your tunnel command. adb kill-server first: a leftover local adb server hides the remote one.
  • Permission denied running ./bin/geniex-bench — the chmod 755 step was skipped. adb push does not preserve execute bits.
  • library ... not found or a dlopen error — the two cp ... *.so staging steps were skipped, or the three environment variables are missing. They must be on the same line as the command; adb shell starts a fresh shell each time.
  • Models with multiple graphs must specify a graph name — you will NOT see this here. GenieX reads genie_config.json and enables the right graphs itself. That error belongs to raw profile jobs (Task 07). If you see it, the bundle push is incomplete.
  • -c 2000 fails — 2000 is not a compiled context length. Only 512/1024/2048/3072/4096 exist in the binaries.
  • Session died mid-run — sessions have a time limit; the UI has Extend Session. If it expired, your files are gone (QDC reflashes the phone) and you start the push again in a new session.
  • The pem is rejected — check file permissions: chmod 600 on the key file. ssh refuses world-readable keys.

12. Knowledge check

  1. You want the sampler temperature at 0.2 instead of 0.8. Recompile?
    AnswerNo. The sampler lives in genie_config.json, read by GenieX at start. It is runtime configuration. You could even edit the pushed copy on the phone and rerun.
  2. You want a context length of 8192. Recompile?
    AnswerYes. Only 512/1024/2048/3072/4096 were compiled into the context binaries. A new length is a new compile job producing new binaries.
  3. Why can this exact bundle not run on a Snapdragon 8 Gen 3 phone, which was also "Available Now" in the catalog?
    AnswerThe context binaries were compiled for sm8750 (HTP v79). A different chipset has a different NPU; the compiled graphs do not load there. Chipset is a compile-time fact.
  4. TTFT and decode tokens/s: which graphs does each one exercise?
    AnswerTTFT is dominated by one pass of the prompt_ar128 prefill graphs. Decode tokens/s comes from repeated token_ar1 passes, one per generated token.
  5. Task 07 measured 24.8 ms per raw part2 decode pass. Your measured decode is 31 ms per token. Where did the 6 ms go?
    AnswerInto everything around the graph: part1, KV-cache handling, sampling the next token, the tokenizer, and GenieX/QAIRT orchestration overhead per step.

14. Page glossary and sources

QDC interactive session
A live reservation of a real device in Qualcomm's lab. You connect through an SSH tunnel and control the device with adb while your minute budget runs.
adb (Android Debug Bridge)
The standard Android command-line tool: push and pull move files, shell runs commands on the device. Here it talks to a remote adb server through the tunnel.
SSH tunnel
An ssh connection used only to forward a local port to a machine you cannot reach directly. -L port:host:5037 makes the remote adb server look local; -N means run no remote command.
geniex-bench
GenieX's benchmark command. Runs the full prefill+decode loop against a model and reports TTFT, prefill tokens/s, and decode tokens/s as JSON cells.
TTFT (time to first token)
Milliseconds from sending the prompt to receiving the first generated token. Dominated by prefill.
Decode tokens per second
Generated tokens divided by generation time after the first token. Dominated by the one-token decode graph, repeated.
